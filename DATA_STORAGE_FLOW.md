The app uses **browser localStorage** to track tasks. The Python scripts were just examples - your actual implementation is 100% TypeScript/React and calls the same REST API endpoints.

## 📊 Data Storage Architecture

### Storage Location
```
Browser localStorage
Key: "eyeway_processing_tasks"
Type: JSON array of ProcessingTask objects
```

### ProcessingTask Interface
```typescript
interface ProcessingTask {
  id: string;              // Internal ID: "task_1234567890_xyz"
  taskId: string;          // Kiri Engine ID: "0bc64b6f39d34d9197de42d6a0bdac51"
  potholeId?: string;      // Optional: Associated pothole
  videoUrl?: string;       // Optional: Local video URL
  createdAt: string;       // ISO timestamp
  status: 'pending' | 'processing' | 'completed' | 'failed';
  progress: number;        // 0-100
  statusMessage?: string;  // Human-readable status
  error?: string;          // Error message if failed
  modelUrl?: string;       // Final model URL
}
```

### Storage Manager Functions
```typescript
// Read
getAllTasks()              → ProcessingTask[]
getTaskById(id)           → ProcessingTask | null
getTaskByKiriId(taskId)   → ProcessingTask | null

// Write
addTask(taskId, videoUrl?, potholeId?) → ProcessingTask
updateTask(id, updates)   → ProcessingTask | null
deleteTask(id)            → boolean
clearCompletedTasks()     → void
```

---

## 🔑 Key Concept: Two IDs

### 1. Internal ID (`id`)
- Generated by browser: `task_${Date.now()}_${random}`
- Example: `"task_1234567890_abc123def"`
- Used for: UI rendering, localStorage keys, React keys

### 2. Kiri Engine ID (`taskId`)
- Generated by Kiri API: response.data.serialize
- Example: `"0bc64b6f39d34d9197de42d6a0bdac51"`
- Used for: API calls (status, download)

## 🐍 Python vs TypeScript - It Doesn't Matter!

The Kiri Engine API is **language-agnostic**. It's a REST API that accepts HTTP requests.

### Python Example
```python
# Python script
resp = requests.post("https://api.kiriengine.app/api/v1/open/3dgs/video",
    headers={"Authorization": f"Bearer {API_KEY}"},
    files={"videoFile": open("video.mp4", "rb")})
task_id = resp.json()["data"]["serialize"]
```

### TypeScript Equivalent (What You're Using)
```typescript
// TypeScript in your app
const result = await uploadVideoToKiriEngine(videoBlob, {...});
const taskId = result.data.serialize;
```

### Both Make The Same HTTP Request:
```http
POST /api/v1/open/3dgs/video HTTP/1.1
Host: api.kiriengine.app
Authorization: Bearer kiri_your_api_key
Content-Type: multipart/form-data

[video file data]
```

### Both Get The Same Response:
```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "serialize": "0bc64b6f39d34d9197de42d6a0bdac51",
    "calculateType": 3
  },
  "ok": true
}
```

**The API doesn't know or care** whether you're using Python, TypeScript, Java, Go, etc. It just accepts HTTP requests and returns JSON responses.

## 📱 Component Data Flow

### Capture3D.tsx
```typescript
// 1. Upload video
const result = await uploadVideoToKiriEngine(videoBlob);
const taskId = result.data.serialize;

// 2. Store in localStorage
const task = addTask(taskId, capturedVideo, potholeData.id);

// 3. Navigate to processing page
navigate(`/processing/${task.id}`);
```

### ProcessingProgress.tsx
```typescript
// On mount: Load all tasks
const tasks = getAllTasks();
setAllTasks(tasks);

// Auto-refresh active tasks (every 5s)
useEffect(() => {
  const interval = setInterval(() => {
    const activeTasks = tasks.filter(t =>
      t.status === 'pending' || t.status === 'processing'
    );

    for (const task of activeTasks) {
      // Use stored taskId for API call
      const status = await checkTaskStatus(task.taskId);

      // Update localStorage
      updateTask(task.id, {
        status: status.status,
        progress: status.progress,
        statusMessage: '...'
      });
    }
  }, 5000);
}, []);

// Manual refresh
const handleCheckTaskStatus = async (taskId: string) => {
  const status = await checkTaskStatus(taskId);  // ← Uses Kiri Engine ID

  // Find task in localStorage
  const task = tasks.find(t => t.taskId === taskId);

  // Update it
  updateTask(task.id, {
    status: status.status,
    progress: status.progress
  });
};
```

## 🔍 How Status Polling Works

### Automatic Polling (Background)
```typescript
// Runs every 5 seconds when viewing /processing
useEffect(() => {
  if (currentView === 'tasklist') {
    const interval = setInterval(() => {
      refreshAllTasks();  // Checks all active tasks
    }, 5000);
    return () => clearInterval(interval);
  }
}, [currentView]);
```

### Manual Polling (Button Click)
```typescript
// When user clicks "Check Status" button
const handleCheckTaskStatus = async (taskId: string) => {
  // 1. Call API with Kiri Engine task ID
  const status = await checkTaskStatus(taskId);

  // 2. Find task in localStorage by taskId
  const task = getAllTasks().find(t => t.taskId === taskId);

  // 3. Update localStorage with new status
  updateTask(task.id, {
    status: status.status,
    progress: status.progress,
    statusMessage: '...'
  });
};
```

## ✅ Summary

1. **Upload** → Get task ID from Kiri API → Store in localStorage
2. **Poll** → Use stored task ID to check status → Update localStorage
3. **Download** → Use stored task ID to get download link → Save file

The Python scripts were just **examples of how to call the API**. Your app:
- Uses TypeScript instead of Python
- Calls the exact same REST API endpoints
- Stores task IDs in browser localStorage (not a database)
- Works exactly the same way as the Python scripts, just in a different language

**The API is language-agnostic** - it's just HTTP requests and JSON responses! 🚀
